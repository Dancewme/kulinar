ТЗ: Веб-приложение «Кулинарный трекер» (облачная версия)
=========================================================

1. ЦЕЛЬ
------
Веб-приложение — список еды по категориям (To-Do лист для еды) с разделением
прав Админ / Гость.

Сайт работает круглосуточно и не зависит от того, включён ли ПК владельца:
бэкенд и БД размещаются в облаке на бесплатных тарифах.

- Фронтенд — один файл index.html, деплой на GitHub Pages.
- Бэкенд — облачный хостинг Render (free Web Service), адрес постоянный
  вида https://<имя-сервиса>.onrender.com.
- БД — Turso (облачный libSQL, SQLite-совместимый), доступ по сети.

Никаких рецептов, описаний, фото. Только названия категорий и блюд.


2. СТЕК (СТРОГО)
----------------
- Python 3.11+, FastAPI, Uvicorn.
- Драйвер БД: пакет `libsql` — официальный Turso SDK с синхронным
  sqlite3-совместимым API. Есть готовые wheels для Linux (Render) и
  Windows (локальная разработка), нативные сборки не требуются.
- Фронт: один index.html, Vanilla JS, без сборки, без фреймворков.
- БД: Turso (libSQL).
- Хостинг: Render free + Turso free. Локальный ngrok — НЕ используется.
- ORM, миграции, лишние зависимости — не использовать.
- requirements.txt: fastapi, uvicorn[standard], libsql.

4. СХЕМА БД
-----------
CREATE TABLE IF NOT EXISTS categories (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE
);

CREATE TABLE IF NOT EXISTS dishes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    category_id INTEGER NOT NULL,
    name TEXT NOT NULL,
    FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS meta (
    key TEXT PRIMARY KEY,
    value TEXT
);

CREATE TABLE IF NOT EXISTS tokens (
    token TEXT PRIMARY KEY,
    created_at INTEGER NOT NULL
);

Схема создаётся при старте приложения (CREATE TABLE IF NOT EXISTS).

ВАЖНО: соединение с БД открывается заново на каждый запрос, и
PRAGMA foreign_keys = ON выполняется сразу после подключения — иначе
каскадное удаление блюд при удалении категории работать не будет.

При удалении категории блюда дополнительно удаляются явным DELETE в той же
транзакции — страховка на случай, если PRAGMA окажется неактивна.

Сортировка вывода везде: ORDER BY id ASC.
Тогда новое блюдо автоматически попадает в конец списка своей категории,
а новая категория — в конец левой панели.


5. НАЧАЛЬНОЕ ЗАПОЛНЕНИЕ
-----------------------
- Выполняется ровно один раз — при первом старте приложения, если в meta
  нет записи initialized=1.
- После заполнения записать initialized=1.
- Если пользователь потом удалит все категории — заново НЕ заполнять.
- Начальные данные:
    Категория: Супы
    Блюда в порядке: Борщ, Харчо, Гаспачо


6. ПЕРЕМЕННЫЕ ОКРУЖЕНИЯ БЭКЕНДА
-------------------------------
Обязательные:

DATABASE_URL — адрес БД Turso (libsql://... или https://...).
  Для локальной разработки допускается file:local.db.
  Если не задана — бэкенд падает при старте.

ALLOWED_ORIGIN — список origins через запятую, например:
  ALLOWED_ORIGIN=https://<username>.github.io,http://localhost:5500,http://127.0.0.1:5500
  Если не задана — бэкенд падает при старте.
  allow_origins=["*"] запрещено.

Опциональные:

TURSO_AUTH_TOKEN — токен доступа к БД Turso. Обязателен для удалённой БД,
  для file:-режима не нужен.

ADMIN_PASSWORD — пароль админа. Если переменная не задана, используется
  fallback "admin123".

Жёсткие правила:
- Секреты (DATABASE_URL, TURSO_AUTH_TOKEN, ADMIN_PASSWORD) НИКОГДА не
  хардкодятся в коде и не коммитятся в репозиторий. На Render задаются
  в дашборде (Environment). Локально — в переменных окружения оболочки.
- Пароль админа хранится ТОЛЬКО на бэкенде. Он НИКОГДА не должен
  появляться в index.html, CSS, JS, в ответах API, в логах фронта.
  На фронт уходит только токен после успешного логина.


7. АВТОРИЗАЦИЯ
--------------
- POST /api/login принимает { "password": "..." }.
    Верно -> сгенерировать токен secrets.token_urlsafe(32), сохранить
             в таблицу tokens { token, created_at },
             вернуть { "token": "..." }.
    Неверно -> 401 { "error": "Invalid password" }.
  Сравнение пароля — secrets.compare_digest.

- Таблица tokens очищается при старте приложения: токены живут в рамках
  одного запуска процесса (сервис на Render может перезапускаться, поэтому
  in-memory словарь не используется).

- Все изменяющие запросы (POST, PUT, DELETE) требуют заголовок
  Authorization: Bearer <token>.

- Нет токена или неверный -> 401 { "error": "Unauthorized" }.

- Фронт хранит токен в localStorage. При любом 401 — стирает токен,
  переключается в режим гостя, показывает сообщение
  «Сессия истекла, войдите заново».

- Вся реальная защита — на бэкенде. Скрытие кнопок на фронте — только UX.


8. API-КОНТРАКТ
---------------
Базовый URL — BACKEND_URL (см. п.9). Все ответы JSON.
Формат ошибок: { "error": "<сообщение>" }.

GET /api/health
  Доступ: все
  Ответ: { "status": "ok" }

GET /api/menu
  Доступ: все
  Ответ: { "categories": [
             { "id": 1, "name": "Супы",
               "dishes": [ { "id": 1, "name": "Борщ" } ] }
           ] }
  Ошибки: 500

POST /api/login
  Доступ: все
  Тело: { "password": "..." }
  Ответ: { "token": "..." }
  Ошибки: 401

POST /api/categories
  Доступ: админ
  Тело: { "name": "Салаты" }
  Ответ: { "id": 2, "name": "Салаты" }
  Ошибки: 400, 401, 409

PUT /api/categories/{id}
  Доступ: админ
  Тело: { "name": "Новое имя" }
  Ответ: { "id": 2, "name": "Новое имя" }
  Ошибки: 400, 401, 404, 409

DELETE /api/categories/{id}
  Доступ: админ
  Ответ: { "ok": true }
  Ошибки: 401, 404

POST /api/dishes
  Доступ: админ
  Тело: { "category_id": 1, "name": "Окрошка" }
  Ответ: { "id": 5, "name": "Окрошка" }
  Ошибки: 400, 401, 404

PUT /api/dishes/{id}
  Доступ: админ
  Тело: { "name": "Новое имя" }
  Ответ: { "id": 5, "name": "Новое имя" }
  Ошибки: 400, 401, 404

DELETE /api/dishes/{id}
  Доступ: админ
  Ответ: { "ok": true }
  Ошибки: 401, 404

Правила:
- Пустое имя после trim -> 400 { "error": "Name is required" }.
- Имя (категории или блюда) длиннее 100 символов ->
  400 { "error": "Name too long" }.
- Невалидное тело запроса (тело отсутствует, не JSON, нет обязательного
  поля, неверный тип) -> 400 { "error": "..." } — через кастомный handler
  RequestValidationError; стандартный 422 FastAPI не использовать.
- Дубликат имени категории -> 409 { "error": "Category already exists" }.
- PUT категории с тем же именем, что и раньше у неё самой, разрешён
  (не считается дубликатом самого себя).
- Дубликаты блюд внутри одной категории — РАЗРЕШЕНЫ (409 только для
  категорий).
- Несуществующий id -> 404 { "error": "Not found" }.
- Удаление категории удаляет её блюда (каскад).
- CORS: allow_origins=[список из ALLOWED_ORIGIN],
        allow_methods=["GET","POST","PUT","DELETE","OPTIONS"],
        allow_headers=["Content-Type","Authorization"].


9. ФРОНТЕНД
-----------
Один файл index.html. В самом верху <script>:

const BACKEND_URL = "https://<имя-сервиса>.onrender.com";

Поведение:
- При загрузке — GET /api/menu, рендер двух панелей.
- Все пользовательские строки — через textContent, не innerHTML
  (защита от XSS).
- После любого успешного POST/PUT/DELETE — перезапросить /api/menu
  и перерисовать.
- Удаление — через confirm().
- Ошибки сети -> сообщение «Не удалось подключиться к серверу».

Сообщения — в баннере под шапкой:
- ошибки API — текст из поля {"error": ...} ответа;
- ошибка сети — «Не удалось подключиться к серверу»;
- любой 401 — «Сессия истекла, войдите заново» + сброс в режим гостя.


10. UI/UX
---------
Макет — двухпанельный (как Проводник Windows):

  +----------------------------------------------------------+
  |  Кулинарный трекер             [Вход для админа / Выйти] |
  +-----------------+----------------------------------------+
  |  Категории      |  Блюда: Супы                           |
  |                 |                                        |
  |  - Супы    р х  |  - Борщ                            р х |
  |  - Салаты  р х  |  - Харчо                           р х |
  |  - Десерты р х  |  - Гаспачо                         р х |
  |                 |                                        |
  |  [+ Категория]  |  [+ Блюдо]                             |
  +-----------------+----------------------------------------+
  (буквы "р" и "х" здесь — условные обозначения иконок
   редактирования (карандаш) и удаления (крестик))

- Левая панель: список категорий. Активная подсвечена.
  В режиме админа рядом — иконки «Редактировать» и «Удалить».

- Правая панель: блюда активной категории. В режиме админа рядом —
  иконки «Редактировать» и «Удалить».

- Кнопки «+ Категория» / «+ Блюдо» — внизу соответствующей панели,
  только в режиме админа.

- Вход: клик «Вход для админа» -> инлайн-поле пароля в шапке с кнопками
  «Войти» / «Отмена». Без модалок.

- Добавление: клик «+ Категория» / «+ Блюдо» -> инлайн-инпут внизу панели
  с кнопками «Сохранить» / «Отмена» (тот же паттерн, что при
  редактировании).

- Редактирование — по клику на иконку карандаша название превращается
  в инлайн-инпут с кнопками «Сохранить» / «Отмена».
  Enter — сохранить, Esc — отмена.
  В режиме гостя иконок редактирования нет вообще.

- Автовыбор: при загрузке и после удаления активной категории активной
  становится первая категория слева. Если категорий нет — правая панель
  показывает подсказку.

- После добавления категории — она сразу становится активной,
  а правая панель переключается на неё.

- Пустая категория: в правой панели надпись «Список пуст».

- Нет категорий вообще: в правой панели — «Создайте первую категорию»
  (в режиме админа) или «Пока нет ни одной категории» (в режиме гостя).

Режим гостя:
- Только просмотр. Никаких инпутов, иконок редактирования/удаления,
  кнопок «+».
- Кнопка «Вход для админа» в правом верхнем углу.

Режим админа:
- Всё вышеперечисленное доступно.
- Кнопка в шапке меняется на «Выйти».
- Токен при загрузке страницы не валидируется: первая же мутация с
  недействительным токеном вернёт 401 и сбросит в гостя.

Адаптив:
- Десктоп (>= 768px): две колонки рядом.
- Мобильный (< 768px): левая панель превращается в горизонтальную
  прокручиваемую полоску категорий над списком блюд. Активная выделена.
  Тап по категории переключает блюда снизу.
- Никаких модалок, всё на одной странице.

Стиль:
- Минимализм, тёплые «кулинарные» акценты (терракота / оранжевый),
  нейтральный фон, скруглённые карточки, лёгкие тени.
- Системный шрифт (system-ui), без внешних подключений.
- Иконки редактирования и удаления — маленькие, серые, краснеют
  при наведении, видны только админу.


11. ХОСТИНГ И СВЯЗКА
--------------------
- index.html -> репозиторий GitHub -> GitHub Pages (HTTPS).
- Бэкенд -> Render Web Service (free) из этого репозитория:
    rootDir: backend
    build: pip install -r requirements.txt
    start: uvicorn app:app --host 0.0.0.0 --port $PORT
  Конфигурация — в render.yaml; секреты задаются в дашборде Render.
- БД -> Turso (free): создать базу, получить DATABASE_URL и
  TURSO_AUTH_TOKEN, прописать их в Environment на Render.
- GitHub Pages работает по HTTPS, поэтому BACKEND_URL тоже HTTPS,
  иначе браузер заблокирует запросы (mixed content).
- Локальный тест фронта: python -m http.server 5500 в каталоге docs
  (через file:// не сработает из-за CORS). Origin http://localhost:5500
  или http://127.0.0.1:5500 должен быть указан в ALLOWED_ORIGIN.
- Локальный запуск бэкенда для разработки:
    DATABASE_URL="file:local.db" ALLOWED_ORIGIN="http://localhost:5500" \
        uvicorn app:app --host 127.0.0.1 --port 8000
- Пошаговая инструкция по деплою — DEPLOY.md.

Ограничения бесплатных тарифов (осознанно приняты):
- Render free: сервис засыпает после 15 минут без трафика; первый запрос
  после паузы отвечает до ~1 минуты (cold start). Это не баг.
- Render free: при каждом пробуждении процесс стартует заново — токены
  админа сбрасываются (см. п.7), фронт покажет «Сессия истекла».
- Turso free: 5 ГБ хранения, 500 млн чтений строк/мес — с большим запасом.


12. КРИТЕРИИ ПРИЁМКИ
--------------------
1.  Пустая БД -> при первом старте появляются «Супы -> Борщ, Харчо, Гаспачо».
2.  Гость видит только список: категории слева, блюда справа.
    Ни инпутов, ни иконок редактирования/удаления.
3.  Кнопка «Вход для админа» открывает поле пароля.
4.  Неверный пароль -> сообщение, режим гостя сохраняется.
5.  Верный пароль (admin123) -> появляются формы добавления,
    иконки редактирования и удаления.
6.  Новое блюдо добавляется в конец списка своей категории.
7.  Новая категория появляется в левой панели внизу и сразу
    становится активной.
8.  Клик по категории переключает правую панель.
9.  Пустая категория -> «Список пуст».
10. Нет категорий -> подсказка в правой панели.
11. Редактирование названия блюда/категории работает в режиме админа,
    в режиме гостя недоступно.
12. Удаление категории удаляет её блюда (каскад), активной становится
    первая оставшаяся.
13. Запросы без токена к изменяющим эндпоинтам -> 401.
14. Пароль отсутствует в index.html, CSS и JS.
15. Интерфейс корректно смотрится на 320px и на 1440px.
16. При обрыве сети фронт показывает «Не удалось подключиться к серверу».
17. Невалидное тело запроса -> 400 {"error": "..."} (не 422).
18. Имя длиннее 100 символов -> 400 {"error": "Name too long"}.
19. Дубликаты блюд в одной категории разрешены.
20. GET /api/health возвращает {"status": "ok"}.
21. Повторный старт бэкенда не пересоздаёт начальные данные.
22. После деплоя сайт открывается и работает при выключенном ПК владельца.
23. Данные сохраняются между перезапусками Render (хранятся в Turso).
24. После перезапуска бэкенда старый токен недействителен (401).

API-часть критериев (начальные данные, CRUD, коды ошибок, порядок вывода,
каскад) проверяется скриптом backend/smoke_test.sh как против локального
uvicorn, так и против адреса Render.
